# ClipQuery 部署文档

> 版本：v0.3
> 目标部署形态：单机 Linux 服务器，自建 uvicorn + systemd

---

## 1. 系统要求

### 1.1 硬件推荐

| 场景 | CPU | 内存 | GPU | 磁盘 |
|---|---|---|---|---|
| 开发/小规模 | 4 核 | 16 GB | 无 | 50 GB SSD |
| 生产 | 8 核 | 32 GB | 可选 T4 / 3060 | 200 GB SSD |

**磁盘怎么算**：本地**不保留**完整产物——所有静态文件都在 COS。本地只做中间工作区：
- `news/<id>/video.mp4`：从爬虫到 indexer 完成之间，约 20-80 MB，用完即删
- `data/thumbnails/*.jpg`：单帧缩略图上传瞬间，10-30 KB 级
- `data/clips/<id>/*.mp4`：单片段切出到上传之间，1-5 MB 级

**稳态**：空闲时 `news/` 和 `data/` 接近为零。**峰值**（并发入库 N 条视频）：N × (video.mp4 + 几个片段 + 一张缩略图) ≈ 几十到几百 MB。50 GB SSD 足够。

**GPU 是否必要**：不强制。CLIP 模型 (ViT-B/32) 在 CPU 上文本编码 100-300 ms，图像编码 200-500 ms 可接受。但入库阶段慢 5-10 倍。

### 1.2 操作系统

- Linux：Ubuntu 22.04 / Debian 12 / CentOS Stream 9 均可
- Windows：仅开发用，生产不推荐（文件锁和 ffmpeg 路径差异多）

### 1.3 外部依赖

| 依赖 | 用途 | 备注 |
|---|---|---|
| Python 3.10+ | 运行时 | 代码使用 `str \| None` 等 PEP 604 语法 |
| ffmpeg | HLS 下载、音频抽取、视频切片 | 必须在 PATH 中 |
| AWS OpenSearch 2.x | 向量库 + 元数据 | 已有 CGTN 测试域 |
| 腾讯云 COS | 对象存储 | bucket `video-metainsight-test-1326743305` |

## 2. 安装

### 2.1 克隆代码

```bash
cd /srv
git clone <repo-url> clipquery
cd clipquery
```

### 2.2 Python 环境

```bash
python3.10 -m venv .venv
source .venv/bin/activate
pip install -U pip
pip install -r requirements.txt
```

**依赖说明**（`requirements.txt`）：
- `fastapi` / `uvicorn[standard]` — Web 框架
- `sentence-transformers` / `torch` — CLIP 模型
- `opencv-python` / `Pillow` — 抽帧、图像处理
- `opensearch-py` — OpenSearch 客户端
- `cos-python-sdk-v5` — 腾讯云 COS SDK
- `scenedetect[opencv]` — PySceneDetect，场景检测
- `openai-whisper` — ASR（可选，爬虫用）
- `requests` / `lxml` — 爬虫 HTTP + HTML 解析

**首次运行会从网络下载**：
- CLIP 模型 `clip-ViT-B-32`（约 350 MB，缓存到 `~/.cache/torch`）
- Whisper 模型 `small`（约 500 MB，缓存到 `~/.cache/whisper`）

## 3. 配置

所有配置通过环境变量注入，前缀 `CLIPQUERY_`。

### 3.1 `.env` 文件（推荐）

仓库里有一份 `.env.example` 作模板。首次部署：

```bash
cd /srv/clipquery
cp .env.example .env
chmod 600 .env
vim .env    # 把标 *** 的四个字段换成真实凭据
```

**必须覆盖**（`.env.example` 里标 `***` 的字段）：

| 字段 | 用途 |
|---|---|
| `CLIPQUERY_OPENSEARCH_HOST` | OpenSearch 域名 |
| `CLIPQUERY_OPENSEARCH_PASSWORD` | OpenSearch 密码 |
| `CLIPQUERY_COS_SECRET_ID` | 腾讯云 SecretId |
| `CLIPQUERY_COS_SECRET_KEY` | 腾讯云 SecretKey |

**生产建议打开**：

```dotenv
CLIPQUERY_PROJECT_ROOT=/srv/clipquery
CLIPQUERY_NEWS_DIR=/srv/clipquery/news
CLIPQUERY_DATA_DIR=/srv/clipquery/data
CLIPQUERY_DEVICE=cuda                   # 有 GPU 的话
```

> **原理**：`pydantic-settings` 在 `clipquery/config.py` 里声明 `env_file=".env"`，所以进程启动时会自动读取项目根的 `.env`。无需 `source` 或 `export`。
>
> `.env` 已在 `.gitignore`，不会被提交。`.env.example` 是**可提交的模板**，别把真实凭据写进去。

### 3.2 验证配置

```bash
python -c "from clipquery.config import settings; print(settings.model_dump())"
```

应该打印合并后的全量配置。确认：
- `project_root` 指向你部署的目录
- `opensearch_password` / `cos_secret_id` / `cos_secret_key` 是 `.env` 里真实的值，不是 `***`

### 3.3 验证外部连通性

```bash
# OpenSearch
python -c "
from clipquery.storage.vector_store import get_vector_store
print('frames count:', get_vector_store().count())
"

# COS
python -c "
from clipquery.cos import get_cos
from clipquery.config import settings
r = get_cos().list_objects(Bucket=settings.cos_bucket, MaxKeys=1)
print('cos ok, sample:', r.get('Contents', [{}])[0].get('Key'))
"
```

## 4. 首次跑通

### 4.1 抓一篇新闻（会写 OpenSearch + COS）

编辑 `scripts/crawl_one.py` 里的 `url` 为一条 CGTN transcript 链接，然后：

```bash
source .venv/bin/activate
python scripts/crawl_one.py
```

**期望输出**：
```
[INFO] 处理: https://news.cgtn.com/...
[INFO] 请求列表页: ...
[FFMPEG-STAGE1] ts 临时目录: ...
[OK] 已保存: /srv/clipquery/news/<aid>/video.mp4
[OK] 音频已导出: ...
[ASR] 运行 whisper（进度将实时输出）: ...
[OK] Whisper 字幕: ...
[OK] 完成: /srv/clipquery/news/<aid>
[DONE] info.json:
{
  "id": "...",
  ...
  "cos_video_url": "https://....cos.ap-beijing.myqcloud.com/...",
  ...
}
```

此时 OpenSearch `clipquery_articles` 索引里应该有 1 条文档。

### 4.2 入库该视频（切片 + 抽帧 + 编码）

```bash
python scripts/ingest_cli.py news/
```

**期望输出**：
```
待处理视频: 1
[1/1] /srv/clipquery/news/<aid>/video.mp4
video.mp4: 100%|██████████| 60/60 [00:35<00:00,  1.7frame/s]
  -> 写入 60 帧
完成，累计写入 60 帧
```

### 4.3 起 API 验证

```bash
uvicorn clipquery.api.main:app --host 0.0.0.0 --port 8000
```

另开终端：
```bash
curl http://localhost:8000/health
# {"status":"ok","indexed_frames":60}

curl -X POST http://localhost:8000/search -F 'query=海边' -F 'top_k=3'
# 返回 results
```

### 4.4 一步到位（服务化）

起好 API 后，不用两步走，直接 URL 入库：

```bash
# 异步，立即返回 job_id
curl -X POST http://localhost:8000/ingest \
  -F 'url=https://news.cgtn.com/news/.../index.html'
# → {"job_id":"abc...","status":"queued","article_url":"..."}

# 轮询状态
curl http://localhost:8000/ingest/abc...
# status: queued → crawling → ingesting → done
```

### 4.5 定时增量任务（CGTN 每小时扫一次）

```bash
# 常驻模式：启动后立刻跑一次，之后每小时增量
python -m clipquery.task.cgtn

# 一次性调试
python -m clipquery.task.cgtn --run-once

# 自定义周期（分钟）
python -m clipquery.task.cgtn --interval-minutes 30
```

**行为**：
- 拉 https://www.cgtn.com/transcript 列表
- 对每个 URL 查 `clipquery_articles` 是否已入库（幂等去重）
- 新增 URL 串行跑端到端（爬 + 切片 + 编码 + 三索引）

**生产部署建议**：作为独立 systemd service 跑，不要和 API 共进程。
参考 §5.1 建一份 `clipquery-task-cgtn.service`，`ExecStart` 换成
`/srv/clipquery/.venv/bin/python -m clipquery.task.cgtn`。

## 5. 生产部署（systemd）

### 5.1 写 systemd 服务

`/etc/systemd/system/clipquery.service`：

```ini
[Unit]
Description=ClipQuery API Server
After=network.target

[Service]
Type=simple
User=clipquery
WorkingDirectory=/srv/clipquery
# 注意：这里不用 EnvironmentFile，pydantic-settings 会自己读项目根的 .env。
# systemd 的 EnvironmentFile 对特殊字符（^、$、=）的转义规则跟 dotenv 不同，
# 容易把 OpenSearch 密码 / COS SecretKey 读错。
ExecStart=/srv/clipquery/.venv/bin/uvicorn clipquery.api.main:app \
          --host 0.0.0.0 --port 8000 --workers 1
Restart=on-failure
RestartSec=5

# 资源限制
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

> **⚠️ `--workers 1` 不是笔误**。入库任务队列 `_JOBS` 是进程内 dict，多 worker 下查询 `/ingest/{job_id}` 可能落到别的 worker 导致 404。
> 要水平扩展，上 Celery / RQ 把队列外置到 Redis。

### 5.2 启用

```bash
sudo useradd -r -s /usr/sbin/nologin clipquery
sudo chown -R clipquery:clipquery /srv/clipquery
sudo systemctl daemon-reload
sudo systemctl enable --now clipquery
sudo systemctl status clipquery
```

### 5.3 查看日志

```bash
journalctl -u clipquery -f
```

### 5.4 Nginx 反向代理（可选）

`/etc/nginx/sites-available/clipquery`：

```nginx
server {
    listen 80;
    server_name clipquery.internal;

    # 可选：IP 白名单
    # allow 10.0.0.0/8;
    # deny all;

    client_max_body_size 500M;         # 允许上传大视频

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 600s;       # 搜图上传耗时放宽
    }
}
```

## 6. GPU 部署差异

### 6.1 安装 CUDA 版 torch

```bash
# 以 CUDA 12.1 为例
pip install torch --index-url https://download.pytorch.org/whl/cu121
```

### 6.2 配置

```dotenv
CLIPQUERY_DEVICE=cuda
CLIPQUERY_BATCH_SIZE=64        # GPU 内存大可以调高
```

### 6.3 验证

```bash
python -c "
import torch
print('cuda:', torch.cuda.is_available())
print('device:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'cpu')
"
```

### 6.4 多 Whisper / CLIP 并发注意

单 GPU 上同时跑多个 ingest 任务会 OOM。目前代码没有 GPU 并发控制，生产建议：
- `--workers 1`（已经是默认）
- 批量入库用串行 CLI，不并发

## 7. 运维操作

### 7.1 重建某个索引

```bash
python - <<'EOF'
from clipquery.storage.vector_store import get_vector_store
vs = get_vector_store()
vs.client.indices.delete(index=vs.index, ignore=[404])
# 下次 import 会自动重建 mapping
EOF
```

重建 `clipquery_frames` 后，要重新 `ingest_cli.py news/`。

### 7.2 清理某篇新闻

```bash
AID=a1b2c3d4e5f6a7b8

# 本地
rm -rf /srv/clipquery/news/$AID

# OpenSearch
curl -X DELETE "https://$OS_HOST/clipquery_articles/_doc/$AID"
curl -X POST "https://$OS_HOST/clipquery_frames/_delete_by_query" -d '{
  "query": {"term": {"article_id": "'"$AID"'"}}
}'
curl -X POST "https://$OS_HOST/clipquery_clips/_delete_by_query" -d '{
  "query": {"term": {"article_id": "'"$AID"'"}}
}'

# COS（示例，需带凭据签名）
python - <<EOF
from clipquery.cos import get_cos
from clipquery.config import settings
c = get_cos()
keys = [o["Key"] for o in c.list_objects(
    Bucket=settings.cos_bucket,
    Prefix=f"ClipQuery/$AID/"
).get("Contents", [])]
for k in keys:
    c.delete_object(Bucket=settings.cos_bucket, Key=k)
print(f"deleted {len(keys)} objects")
EOF
```

### 7.3 磁盘水位

```bash
du -sh /srv/clipquery/news /srv/clipquery/data
df -h /srv
```

本地现在只是临时工作区。如果 `news/` 里长期有残留目录，通常说明 indexer 曾经失败——检查对应 article_id 的 OpenSearch `clipquery_frames` 文档数：
```bash
# 有残留的 news/<aid> 里 video.mp4 都是等待重新 ingest 的
ls news/
# 对每个 aid 检查入库状态
python -c "
from clipquery.storage.vector_store import get_vector_store
vs = get_vector_store()
print(vs.video_frame_count('/srv/clipquery/news/<aid>/video.mp4'))
"
# 为 0 → 重跑 ingest；> 0 → 可以直接 rm -rf news/<aid>
```

## 8. 常见问题排查

### 8.1 `ImportError: libGL.so.1: cannot open shared object file`

OpenCV 缺依赖：
```bash
sudo apt-get install -y libgl1 libglib2.0-0
```

### 8.2 CLIP 模型下载超时

首次运行需要联网下载模型文件 350 MB。内网机器：
```bash
# 在有网机器上下好 ~/.cache/torch/sentence_transformers/
# 整个目录 rsync 到服务器
rsync -av ~/.cache/torch/sentence_transformers/ server:~/.cache/torch/sentence_transformers/
```

### 8.3 Whisper 卡住没进度

`subprocess.run()` 的 `capture_output=True` 会吃掉 whisper 的进度条。代码里已去掉，若仍卡住：
- 换小模型 `--model base`
- 或禁用 Whisper，让 `paragraphs_to_srt()` 兜底

### 8.4 OpenSearch KNN 返回空

- 确认 `embedding_dim` 和 mapping 一致（默认 512，换模型别忘了改）
- `refresh` 是否被跳过（高吞吐场景下 `vector_store.refresh()` 可能被关闭）

### 8.5 COS 403 AccessDenied

- `SecretId/SecretKey` 过期或没有对应 bucket 的 `PutObject` 权限
- bucket region 和 `cos_region` 不匹配（bucket 名字尾部 `-1326743305` 是 AppID，不代表 region）

### 8.6 FastAPI `/ingest` 永远 queued

- 确认只跑了 1 个 worker
- 检查进程是否被 OOM killer 杀了：`dmesg | grep clipquery`
- 检查磁盘：`df -h`

## 9. 安全

当前默认配置里**凭据是测试值**（OpenSearch 密码 + COS 密钥都写在 `config.py`）。**上线必做**：

### 9.1 覆盖所有敏感字段

在 `.env` 里明文覆盖，确保 `config.py` 里的默认值**不再被使用**：
- `CLIPQUERY_OPENSEARCH_PASSWORD`
- `CLIPQUERY_COS_SECRET_ID`
- `CLIPQUERY_COS_SECRET_KEY`

### 9.2 `.env` 权限

```bash
chmod 600 /srv/clipquery/.env
chown clipquery:clipquery /srv/clipquery/.env
```

### 9.3 API 访问控制

- 加 Nginx 层 IP 白名单（见 §5.4）
- 需要外网暴露时，前面加 Token（在 FastAPI 层加 `Depends(verify_token)`）

### 9.4 COS 公网可读 vs 签名 URL

当前实现**假设 COS bucket 对象是公开读**（因为 URL 直接给前端播放）。如果 bucket 是私有读：
- 改 `clipquery/cos.py` 的 `object_url()` 为 `get_presigned_url()` 带签名
- 签名有效期建议 1–24 小时

## 10. 升级

### 10.1 普通代码更新

```bash
cd /srv/clipquery
git pull
source .venv/bin/activate
pip install -r requirements.txt   # 若 deps 有变
sudo systemctl restart clipquery
```

### 10.2 CLIP 模型升级

升级到维度不同的模型（如 `clip-ViT-L-14` = 768 维）需要：
1. 改 `CLIPQUERY_CLIP_MODEL_NAME` 和 `CLIPQUERY_EMBEDDING_DIM`
2. 删除并重建 `clipquery_frames` 索引
3. 对所有历史视频重新 `ingest_cli.py`
