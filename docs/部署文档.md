# ClipQuery 部署文档

> 版本：v0.5
> 目标形态：Docker 单容器（`Dockerfile`），容器内监听 8000，宿主机映射到 **8008** 对外。

---

## 1. 定位

单容器只做**只读 API**，所有写入由本地脚本驱动：
- `/search` 在线检索
- `/task/{id}` 状态查询
- `/health` 健康检查
- 入队：`docker exec` 进容器跑 `scripts/scan_cgtn.py` / `scripts/pipeline_one.py`
- 消费：`docker exec` 进容器跑 `scripts/consume_one.py`
- CGTN 定时扫可用 crontab/systemd 定期调 `scripts/scan_cgtn.py`（服务进程不再自带）

多实例水平扩时，Redis 锁 + BRPOP 保证互斥，无需额外协调。

---

## 2. 外部依赖

| 依赖 | 用途 | 备注 |
|---|---|---|
| **Redis 6+（TLS）** | **任务队列 + 元数据 + 分布式锁**（本地脚本消费层使用） | AWS ElastiCache for Redis |
| OpenSearch 2.x | 向量库 + 元数据 | AWS OpenSearch 托管域 |
| 腾讯云 COS | 片段 / 缩略图 / 原片归档 | 需 `PutObject` + `GetObject` + `DeleteObject`（force 清理要） |
| CGTN 网站 | 新闻来源 | 需能连 https://news.cgtn.com |
| ffmpeg | 容器内自带（Dockerfile 装的） | HLS 下载 / 切片 / 抽音 |
| Whisper（可选） | 字幕生成 | 没模型时 fall back 到 paragraphs 兜底 |

---

## 3. 硬件推荐

| 场景 | CPU | 内存 | GPU | 磁盘 |
|---|---|---|---|---|
| 开发 / 低吞吐 | 4 核 | 8 GB | 无 | 20 GB |
| 生产（单副本，日 100+ 视频） | 8 核 | 16 GB | 可选 T4 / 3060 | 50 GB |
| 多副本横向扩 | 每副本 4 核 / 8 GB | — | 按预算 | 20 GB / 副本 |

**磁盘估算**：本地不保留完整产物——所有静态文件都在 COS。本地只是临时工作区：
- `news/<id>/video.mp4`：从爬虫到 indexer 完成之间，20–80 MB。
- `data/thumbnails/*.jpg`：单帧缩略图上传瞬间，10–30 KB。
- `data/clips/<id>/*.mp4`：单片段切出到上传之间，1–5 MB。

稳态下 `news/` 和 `data/` 接近空。峰值（并发入库 N 条）≈ 几百 MB。

## 5. 本地启动（不走 Docker）

开发机直接跑 Python，方便断点调试和看报错。下面的命令**Windows PowerShell 和 Linux/macOS 都能用**（差异处会标出）。

### 5.0.1 前置

| 项 | 版本 | 说明 |
|---|---|---|
| Python | 3.11（推荐） / 3.10 也可 | `python --version` 核对 |
| ffmpeg | 任意较新版 | **必须在 PATH**：`ffmpeg -version` 能跑通；Windows 用 scoop/choco/官网安装包；Linux `apt install ffmpeg`；macOS `brew install ffmpeg` |
| 磁盘 | 预留 10 GB | CLIP 模型 ~600 MB + 视频工作区 |
| 网络 | 能连 OpenSearch / Redis / COS | 公司内网 VPC 的话需要先跳板机或 VPN |

### 5.0.2 克隆并建虚拟环境

```bash
git clone <repo> clipquery
cd clipquery

# Windows (PowerShell)
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# Linux / macOS
python3 -m venv .venv
source .venv/bin/activate
```

### 5.0.3 安装依赖

`requirements.txt` 里 `torch` 没锁 CPU/GPU 源，先手工装一次，再装其它：

```bash
# CPU 版 torch（开发机一般够用）
pip install --index-url https://download.pytorch.org/whl/cpu "torch>=2.2.0"

# 其余依赖
pip install -r requirements.txt
```

有 NVIDIA 显卡想用 GPU：`pip install torch --index-url https://download.pytorch.org/whl/cu121`，再把 `.env` 里 `CLIPQUERY_DEVICE=cuda`。

### 5.0.4 配置 `.env`

```bash
cp .env.example .env     # Windows: copy .env.example .env
```

打开 `.env`，**至少**覆盖以下四项（其它保持默认即可，模板里已经有测试环境可用的值）：

```dotenv
CLIPQUERY_OPENSEARCH_PASSWORD=***
CLIPQUERY_REDIS_PASSWORD=***
CLIPQUERY_COS_SECRET_ID=***
CLIPQUERY_COS_SECRET_KEY=***
```

`.env` 的位置由 `clipquery/config.py` 定死在**项目根目录**，和启动时的 cwd 无关。

### 5.0.5 预拉 CLIP 模型（可选，但强烈建议）

首次 import encoder 会从 HuggingFace 下 `clip-ViT-B-32`（~600 MB）。离线或网络慢时先拉下来：

```bash
# 需要 pip install -U "huggingface_hub[cli]"
hf download sentence-transformers/clip-ViT-B-32 --local-dir ./data/clip-ViT-B-32
```

`.env.example` 已经把 `HF_ENDPOINT=https://hf-mirror.com` 作为默认值，国内直接能下。

### 5.0.6 启动 API

```bash
uvicorn clipquery.main:app --host 0.0.0.0 --port 8000 --reload
```

`--reload` 是开发用，改代码自动重启；生产去掉。第一次启动会：
- 创建 `data/`、`news/`、`data/thumbnails/` 等目录
- 连 OpenSearch 若索引不存在会**自动建**（`_ensure_index`）
- 连 Redis 但不消费队列（API 进程只做入队）

成功输出大致：

```
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
INFO:     Application startup complete.
2026-11-10 ... INFO clipquery: ClipQuery API 启动 worker_id=app-... (只做 API，不消费队列)
```

### 5.0.7 验证

```bash
curl http://localhost:8000/health
# {"status":"ok","worker_id":"app-...","indexed_frames":0,"indexed_subtitles":0,"queue_length":0}
```

### 5.0.8 本地跑数据处理脚本

API 进程**不消费队列**，所有入库动作都要靠 `scripts/` 下的脚本手动触发（这是设计选择，见架构文档）。常用三条：

```bash
# 1) 端到端跑一篇文章（最常用的手动触发入口）
#    默认 URL 在脚本里写死；也可以传参
python scripts/pipeline_one.py
python scripts/pipeline_one.py "https://news.cgtn.com/news/2026-11-03/.../index.html"

# 2) 扫 CGTN 列表页 → 把新文章入 Redis 队列
python scripts/scan_cgtn.py

# 3) 从队列取一条执行（配合上一步使用）
python scripts/consume_one.py         # 处理一条退出
python scripts/consume_one.py --all   # 把队列里积压的任务全跑完
```

辅助脚本：

| 脚本 | 用途 |
|---|---|
| `scripts/crawl_one.py` | 只爬文章 + 下视频，不做索引（调试爬虫用） |
| `scripts/wipe_all.py` | **危险操作**：一键清空 Redis + OpenSearch + COS 的所有 ClipQuery 数据 |

### 5.0.9 验证检索

跑完至少一篇文章后：

```bash
# 文本搜
curl -X POST http://localhost:8000/search \
  -F "query=people walking on the street" \
  -F "top_k=5"

# 台词搜（基于 SRT + CLIP 文本编码的 KNN）
curl -X POST http://localhost:8000/search_subtitle \
  -F "query=climate change" \
  -F "top_k=5"
```

### 5.0.10 本地启动常见坑

| 症状 | 原因 / 解决 |
|---|---|
| `FileNotFoundError: ffmpeg` | ffmpeg 没在 PATH。Windows 装完要开**新**终端，或重启 IDE |
| `ImportError: libGL.so.1`（Linux） | `apt install -y libgl1 libglib2.0-0` |
| `redis.exceptions.ConnectionError` | 不在 VPC 内 / 没走跳板机，`CLIPQUERY_REDIS_SSL=true` 没开 |
| CLIP 首次加载卡住 | 代理/防火墙拦 huggingface.co；确认 `.env` 或 shell 有 `HF_ENDPOINT=https://hf-mirror.com` |
| `pydantic.ValidationError` 启动失败 | `.env` 里字段名拼错，`CLIPQUERY_` 前缀必须保留 |
| OpenSearch `illegal_argument_exception` 关于 `knn_vector` | OpenSearch 域没开 k-NN 插件；换环境或换到支持 KNN 的域 |
| Whisper 很慢 / 下不了模型 | 它默认 CPU 跑 small 模型。想关 ASR 走 paragraphs 兜底：改 `clipquery/website/cgtn/pipeline.py` 的 `has_whisper()` 返回 False，或者卸载 openai-whisper |

## 6. Docker 部署

### 6.1 构建镜像

```bash
cd /srv/clipquery
cp .env.example .env    # 填入真实凭据
docker build -t clipquery:latest .
```

**镜像内容**：Python 3.11 + CPU 版 torch + CLIP 模型预拉 + ffmpeg + Redis 客户端。首次构建约 10–15 分钟，之后改代码几十秒命中缓存。

### 6.2 启动（单实例）

> **⚠️ 首次启动前必读：预种 CLIP 模型到 data 卷**
>
> Dockerfile 在 `/app/data/clip-ViT-B-32` 预拉好了 CLIP 模型（~600 MB），
> 但如果直接挂 `-v clipquery-data:/app/data`，**空的 Docker volume 会把镜像里的模型目录整个覆盖掉**，
> 结果容器首次 `/search_subtitle` 时去 HuggingFace 重新下载，常见症状：
>
> - 首次查询卡 10–30 秒
> - 运行时报 `RuntimeError: 下载模型失败: ... No space left on device (os error 28)`
>   （容器 overlay fs / `/tmp` 空间不足时）
>
> 解决：**先用一次性容器把镜像里的预拉模型 copy 进卷，再正式起服务。**
>
> ```bash
> # 1) 把镜像内自带的模型复制到命名卷
> docker run --rm \
>   -v clipquery-data:/target \
>   clipquery:latest \
>   cp -r /app/data/clip-ViT-B-32 /target/
>
> # 2) 校验卷里有东西（应能看到 modules.json、model.safetensors 等）
> docker run --rm -v clipquery-data:/data alpine ls -la /data/clip-ViT-B-32
> ```
>
> 已做过这步、或升级后模型 repo 未变，可跳过。想换模型版本时也要重跑一次（或直接 `docker volume rm clipquery-data` 让卷重建）。

```bash
docker run -d --name clipquery \
  -p 8008:8000 \
  -v $PWD/.env:/app/.env:ro \
  -v clipquery-news:/app/news \
  -v clipquery-data:/app/data \
  --restart unless-stopped \
  clipquery:latest
```

> 端口说明：容器内 uvicorn 仍监听 `8000`，宿主机通过 `-p 8008:8000` 对外暴露 **8008**。后续所有宿主机侧的 curl / 浏览器访问都走 `http://<host>:8008`。

启动后应看到：
```bash
docker logs -f clipquery
# ... ClipQuery API 启动 worker_id=app-xxx-1-abcd (只做 API，不消费队列)
# ... Uvicorn running on http://0.0.0.0:8000
```

### 6.3 验证

```bash
# 服务存活（宿主机侧访问 8008，容器内是 8000）
curl http://localhost:8008/health
# {"status":"ok","worker_id":"app-...","indexed_frames":0,"queue_length":0}

# 推一条任务（服务端无 HTTP 入队接口，用容器里的脚本）
docker exec -it clipquery python scripts/pipeline_one.py \
  "https://news.cgtn.com/news/2026-11-03/VHJhbnNjcmlwdDkzMTAw/index.html"

# 轮询状态（HTTP）
curl -s http://localhost:8008/task/ingest-xxxx | jq .
# state: queued → in_progress → done
```

> 注意：Docker 容器也**不消费队列**。执行任务仍需在**宿主机或另一个容器里**跑 `python scripts/consume_one.py`（容器里可以 `docker exec -it clipquery python scripts/consume_one.py --all`）。

### 6.4 水平扩

多起几个容器，端口各自映射，前面放 LB：

```bash
for i in 1 2 3; do
  docker run -d --name clipquery-$i \
    -p $((8008 + i)):8000 \
    -v $PWD/.env:/app/.env:ro \
    -v clipquery-news-$i:/app/news \
    -v clipquery-data:/app/data \
    --restart unless-stopped \
    clipquery:latest
done
```

**约定**：
- `clipquery-news` 每个副本一个独立卷（Worker 之间不需要共享原片）。
- `clipquery-data` 若同时在多个副本里跑 `scripts/pipeline_one.py` 等入库脚本，仍建议共享（便于任一副本的 consume 脚本都能读到中间产物）。

> **生产提示**：`uvicorn --workers 1` 是**强制的**。MCP 的 session manager 是进程级单例，多 worker 会出现会话丢失。想高吞吐就扩容器副本数而不是进程数。

## 7. 安全

当前默认配置里**凭据是测试值**（OpenSearch 密码、COS 密钥、Redis 密码都写在 `config.py`）。上线必做：

### 7.1 覆盖敏感字段

```dotenv
CLIPQUERY_OPENSEARCH_PASSWORD=***
CLIPQUERY_COS_SECRET_ID=***
CLIPQUERY_COS_SECRET_KEY=***
CLIPQUERY_REDIS_PASSWORD=***
```

### 7.2 `.env` 权限

```bash
chmod 600 /srv/clipquery/.env
```

容器内挂载用 `:ro` 只读（见 §6.2）。

### 7.3 访问控制

- 加 Nginx 层 IP 白名单（见 §8）。
- 对外暴露时前面加 Token，FastAPI 侧加 `Depends(verify_token)`。

### 7.4 Redis TLS

ElastiCache for Redis 默认开 TLS，`CLIPQUERY_REDIS_SSL=true` 必须打开。生产不要用明文 6379。

### 7.5 COS 公开读 vs 签名 URL

当前实现假设 bucket 公开读（URL 直接给前端播放）。若 bucket 私有：
- 改 `clipquery/cos.py` 的 `object_url()` 为 `get_presigned_url()` 带签名。
- 签名 TTL 建议 1–24 小时。

## 8. Nginx 反向代理（可选）

`/etc/nginx/sites-available/clipquery`：

```nginx
server {
    listen 80;
    server_name clipquery.internal;

    # IP 白名单
    # allow 10.0.0.0/8;
    # deny all;

        proxy_pass http://127.0.0.1:8008;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 60s;
    }
}
```

## 9. 运维

### 9.1 日志

```bash
docker logs -f clipquery
```

uvicorn 访问日志 + 应用日志混在 stdout。生产建议前置 Fluent Bit / Vector 转 ELK。

### 9.2 查看队列积压

```bash
# 容器内
docker exec -it clipquery python - <<'EOF'
from clipquery.queue import get_queue
q = get_queue()
print("queue_length:", q.queue_length())
print("ping:", q.ping())
EOF

# 或直接 redis-cli
redis-cli -h $REDIS_HOST -p 6379 --tls -a $REDIS_PWD LLEN ClipQuery:ingest:queue
```

### 9.3 查看任务状态分布

```bash
docker exec -it clipquery python - <<'EOF'
from clipquery.queue import get_queue
q = get_queue()
c = q.client
keys = c.keys("ClipQuery:task:*")
from collections import Counter
states = Counter(c.hget(k, "state") for k in keys)
print(states)
EOF
```

### 9.4 手动重跑失败任务

```bash
docker exec -it clipquery python - <<'EOF'
from clipquery.queue import get_queue, TaskState
import json
q = get_queue()
c = q.client
for k in c.keys("ClipQuery:task:*"):
    if c.hget(k, "state") != TaskState.FAILED:
        continue
    task_id   = c.hget(k, "task_id")
    task_type = c.hget(k, "task_type")
    payload   = json.loads(c.hget(k, "payload") or "{}")
    q.enqueue(task_id, task_type, payload)
    print("requeued", task_id)
EOF
```

或者直接 `docker exec -it clipquery python scripts/pipeline_one.py <url> --force` 重跑（会额外清掉旧 OpenSearch / COS 产物）。

### 9.5 清掉某篇新闻（手动）

一般用 `scripts/pipeline_one.py <url> --force` 就足够。要彻底不重跑，直接调 purge：

```bash
docker exec -it clipquery python - <<'EOF'
from clipquery.task.purge import purge_article
print(purge_article("a1b2c3d4e5f6a7b8", drop_task_meta=True))
EOF
```

### 9.6 重建某个索引

```bash
docker exec -it clipquery python - <<'EOF'
from clipquery.storage.vector_store import get_vector_store
vs = get_vector_store()
vs.client.indices.delete(index=vs.index, ignore=[404])
# 下次 import 自动重建 mapping
EOF
```

重建 `clipquery_frames` 后要重跑所有视频入库。

### 9.7 优雅重启

```bash
docker restart clipquery

# 多副本滚动
for i in 1 2 3; do
  docker stop clipquery-$i && docker rm clipquery-$i
  docker run -d --name clipquery-$i \
    -p $((8008 + i)):8000 \
    -v $PWD/.env:/app/.env:ro \
    -v clipquery-news-$i:/app/news \
    -v clipquery-data:/app/data \
    --restart unless-stopped \
    clipquery:latest
done
```

实例收 SIGTERM 后 lifespan 停消费线程。进行中任务由 Redis 锁 TTL（30 分钟）兜底。

## 10. 常见问题

### 10.1 启动失败：`Redis connection refused` / `WRONGPASS`

- 检查 `.env` 里 `CLIPQUERY_REDIS_HOST/PASSWORD/SSL`。
- ElastiCache 一般只在 VPC 内可达：`docker exec clipquery python -c "import redis; print(redis.Redis(host='$HOST', port=6379, password='$PWD', ssl=True).ping())"`。
- 安全组放行 6379。

### 10.2 CGTN 扫不到新文章

- `docker exec clipquery python -m clipquery.task.cgtn --run-once -v` 看日志。
- 常见原因：列表页 HTML 结构变了（`transcript.py` 的 XPath 要跟着改）。

### 10.3 Whisper 卡住或 OOM

- 首次运行需联网下 ~500 MB 模型：`HF_ENDPOINT=https://hf-mirror.com` 走镜像，或 rsync 预下载的 `~/.cache/whisper` 进容器。
- 换小模型：`--model base`（代码里改 `whisper.load_model(...)` 的参数）。

### 10.4 任务永远 queued

- 消费线程挂了 → 容器日志里看有没有 `[consumer] 异常`，再检查 Redis 连通。
- 队列长度一直涨 → 处理速度跟不上，扩副本或开 GPU。

### 10.5 任务永远 in_progress

- 持锁的实例进程挂了，但锁还没到 TTL（默认 1800s）。等自动过期或手动 `DEL ClipQuery:lock:<task_id>`。

### 10.6 `ImportError: libGL.so.1`

OpenCV 缺依赖。Dockerfile 已装 `libgl1 libglib2.0-0`，若自建镜像漏装：
```dockerfile
RUN apt-get install -y libgl1 libglib2.0-0
```

### 10.7 CLIP 模型下载超时

Dockerfile build 时已预拉 `clip-ViT-B-32` 到 `/app/data/clip-ViT-B-32`。换模型 repo / 缓存损坏时：
- 构建环境加 `HF_ENDPOINT=https://hf-mirror.com` 重建镜像。
- 或 rsync 外部下好的 `~/.cache/huggingface` 进容器。

### 10.8 `news/` 磁盘涨得很快

- 异常退出留下的残骸：手动 `docker exec -it clipquery python -c "from pathlib import Path; [print(p) for p in Path('/app/news').iterdir() if not (p / 'video.mp4').exists()]"` 列出无视频的残骸目录，直接 `rm -rf`。
- 下载失败但 video.mp4 保留：用 `docker exec -it clipquery python scripts/pipeline_one.py <url> --force` 重跑。

### 11.1 代码更新

```bash
cd /srv/clipquery

docker stop clipquery && docker rm clipquery
docker run -d --name clipquery \
  -p 8008:8000 \
  -v $PWD/.env:/app/.env:ro \

  -v clipquery-data:/app/data \
  --restart unless-stopped \
  clipquery:latest
```

### 11.2 CLIP 模型升级

升级到维度不同的模型（如 `clip-ViT-L-14` = 768 维）需要：
1. 改 `.env` 里 `CLIPQUERY_CLIP_MODEL_NAME` + `CLIPQUERY_EMBEDDING_DIM`。
2. 改 `Dockerfile` 的 `snapshot_download` repo。
3. `docker build` + 重启容器。
4. 删 `clipquery_frames` 索引，让所有视频重跑入库。
