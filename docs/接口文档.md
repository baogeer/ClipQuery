# ClipQuery 接口文档

> 版本：v0.5
> Base URL（本地默认）：`http://localhost:8000`
> 交互式文档（FastAPI 自带）：`/docs` / `/redoc`

单容器单端口，所有 HTTP 端点、CLI 入口、Python 内部契约、Redis / OpenSearch schema 都在本文档。

## 2. HTTP 端点一览

| 方法 | 路径 | 说明 | 底层 |
|---|---|---|---|
| `GET` | `/health` | 健康检查（Redis 连通 + 队列长度 + 库中帧数 / 台词数） | - |
| `POST` | **`/search`** | **CLIP 视觉/图片语义检索** — 文本/图片/混合，命中到"画面" | CLIP 图像编码 + `clipquery_frames` KNN |
| `POST` | **`/search_subtitle`** | **台词语义检索** — 命中到"台词"，返回精确 `start_time` / `end_time`（秒） | CLIP 文本编码 + `clipquery_subtitles` KNN |
| `GET` | `/task/{task_id}` | 查询任务状态（任务由本地脚本投入，不对外开放入队接口） | - |
| `GET` | `/articles` | 已入库文章列表（按 `ingested_at` 倒序，分页，可选 title 搜索） | `clipquery_articles` match / match_all |
| `GET` | `/articles/{article_id}` | 已入库文章详情（完整 `_source`，含 `paragraphs`） | `clipquery_articles` get |
| `/mcp` | **MCP 端点**（Streamable-HTTP + SSE） | 暴露 5 个工具供 Claude Desktop / Cursor / Cline 接入 | 见 §9 |

**两种搜索怎么选**：

| 场景 | 用哪个 | 理由 |
|---|---|---|
| "找一个人在海边奔跑的画面" | `/search` | 画面特征明显，CLIP 图像嵌入最擅长 |
| "找上图这种构图/色调" | `/search`（带 image） | 以图搜图 |
| "找说过'每天都在奔跑'的那一秒" | `/search_subtitle` | 想定位到台词说出口的精确时间 |
| "找谈到 climate change 的新闻" | `/search_subtitle` | 语义主题藏在旁白/对白里，画面不一定体现 |
| "两者都想要" | 两个端点各调一次，前端合并展示 | 当前后端不做融合 |

## 3. `GET /health`

**用途**：确认服务存活 + OpenSearch 连通 + Redis 连通。

**响应 200**：
```json
{
  "status": "ok",
  "worker_id": "app-ip-10-0-1-5-1-a3f2",
  "indexed_frames": 12480,
  "indexed_subtitles": 8640,
  "queue_length": 3
}
```

- `status` — `ok` 表示 Redis 可达；`redis_down` 表示 Redis ping 失败。
- `worker_id` — 本进程 id，用于日志排查 + Redis 锁 owner 匹配。
- `indexed_frames` — `clipquery_frames` 文档数，为 0 说明还没入库过视频。
- `indexed_subtitles` — `clipquery_subtitles` 文档数（台词搜用），为 0 说明还没入过台词。
- `queue_length` — `ClipQuery:ingest:queue` 当前积压长度。

## 4. `POST /search` — CLIP 视觉/图片语义搜

**定位**：按**画面**搜。文本 query 会被 CLIP 编码到视觉空间，与库里**每一帧**的图像向量比对，命中回到帧所属的"可播放片段"。

**什么时候用这个**：
- 用户输入的是场景 / 构图 / 物体的描述（"一个人在海边奔跑"、"sunset over mountains"）。
- 用户直接丢一张参考图找相似画面。

**什么时候别用**（改用 `/search_subtitle`）：
- 用户想按"主播说了什么"、"剧情提到什么"搜（语义藏在台词里）。
- 用户给的是一个具体句子想精确定位到某一秒。

### 4.1 请求（`multipart/form-data`）

| 字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `query` | string | 二选一 | 自然语言描述 |
| `image` | file (jpg/png/...) | 二选一 | 参考图 |
| `top_k` | int | 否，默认 10 | 返回片段数 |

**规则**：`query` 和 `image` **至少提供一个**。两个都给时内部取向量平均再归一化。

### 4.2 请求示例

```bash
# 以文搜
curl -X POST http://localhost:8000/search \
  -F 'query=一个人在海边奔跑' \
  -F 'top_k=5'

# 以图搜
curl -X POST http://localhost:8000/search \
  -F 'image=@reference.jpg' \
  -F 'top_k=5'

# 混合
curl -X POST http://localhost:8000/search \
  -F 'query=sunset over mountains' \
  -F 'image=@mood_ref.jpg'
```

### 4.3 响应 200

```json
{
  "results": [
    {
      "clip_id":       "f3a8c1d9e2b5a7c4d6e9",
      "article_id":    "a1b2c3d4e5f6a7b8",
      "article_url":   "https://news.cgtn.com/news/2026-11-03/....../index.html",
      "title":         "Along the Coast: Running and the Rhythm of the Sea",
      "start_time":    12.0,
      "end_time":      18.0,
      "clip_url":      "https://video-metainsight-test-1326743305.cos.ap-beijing.myqcloud.com/ClipQuery/<article_id>/clips/<clip_id>.mp4",
      "thumbnail":     "https://.../ClipQuery/<article_id>/thumbnails/<frame_id>.jpg",
      "score":         0.874,
      "hit_count":     6,
      "best_frame_id": "d6e9f3a8c1d9e2b5a7c4",
      "paragraphs": [
        "The morning tide brings runners from across the city...",
        "Local residents say the beach run has become a..."
      ]
    }
  ]
}
```

### 4.4 字段语义

| 字段 | 说明 |
|---|---|
| `clip_id` | 片段唯一 id |
| `article_id` | 所属文章 id = sha1(article_url)[:16] |
| `article_url` | CGTN 原文详情页 |
| `title` | 新闻标题 |
| `start_time` / `end_time` | 片段在原视频中的时间范围（秒） |
| `clip_url` | **COS 上独立的 MP4**，可直接 `<video src=...>` |
| `thumbnail` | 命中帧的缩略图 URL（COS） |
| `score` | 余弦相似度 [-1, 1]，通常 > 0.2 才有意义 |
| `hit_count` | 该片段里命中 KNN top-K 的帧数，越高越可信 |
| `paragraphs` | 原新闻正文段落 |

### 4.5 错误

| 状态 | 场景 |
|---|---|
| 400 | `query` 和 `image` 都没给 |
| 500 | OpenSearch 不可达 / CLIP 模型加载失败 |

### 4.6 前端最小集成

```html
<div>
  <h3>{{ result.title }}</h3>
  <a href="{{ result.article_url }}" target="_blank">查看原文</a>
  <video src="{{ result.clip_url }}" poster="{{ result.thumbnail }}" controls></video>
  <p>命中时间段：{{ result.start_time }}s - {{ result.end_time }}s</p>
  <p>相似度：{{ (result.score * 100).toFixed(1) }}%</p>
</div>
```

## 5. `POST /search_subtitle` — 台词语义搜

**定位**：按**台词**搜，命中带**精确到秒**的 `start_time` / `end_time`，前端可以直接 seek 到这个时间点播。

**原理**：入库时每条 SRT cue 过一次 CLIP 文本编码写进 `clipquery_subtitles`（和 `clipquery_frames` 共用 512d 向量空间）。查询时把 query 也编码成 512d，在台词索引里做 KNN。

**什么时候用这个**：
- 用户给了一句具体台词（"每天都在奔跑"）要找说过这话的点。
- 用户想按新闻**话题**搜（"climate change"、"冬奥会"），但画面不一定直接体现，主播会说出来。
- 需要**秒级精度**（用户按 `start_time` 跳转，而不是播整段片段）。

### 5.1 请求（`multipart/form-data`）

| 字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `query` | string | ✅ | 要搜的台词 / 主题。中英文都行。 |
| `top_k` | int | 否，默认 10 | 返回条数。台词粒度比帧小，建议 5-20。 |

**注意**：**不支持 image**（台词搜只针对文本语义）。要按画面搜去用 `/search`。

### 5.2 请求示例

```bash
# 中文台词
curl -X POST http://localhost:8000/search_subtitle \
  -F 'query=每天都在奔跑' -F 'top_k=5'

# 英文主题
curl -X POST http://localhost:8000/search_subtitle \
  -F 'query=climate change' -F 'top_k=10'
```

### 5.3 响应 200

```json
{
  "results": [
    {
      "article_id":       "a1b2c3d4e5f6a7b8",
      "article_url":      "https://news.cgtn.com/news/.../index.html",
      "title":            "Along the Coast: Running and the Rhythm of the Sea",
      "clip_id":          "f3a8c1d9e2b5a7c4d6e9",
      "clip_url":         "https://.../ClipQuery/<article_id>/clips/<clip_id>.mp4",
      "source_video_url": "https://.../ClipQuery/<article_id>/video.mp4",
      "start_time":       47.2,
      "end_time":         51.8,
      "text":             "Every morning they come to the coast, running with the tide",
      "score":            0.812
    }
  ]
}
```

### 5.4 字段语义

| 字段 | 说明 |
|---|---|
| `article_id` | 所属文章 id |
| `article_url` | CGTN 原文详情页 |
| `title` | 新闻标题 |
| `clip_id` | 台词时间点落在哪个可播放片段（可能为 null，如果没切到片段） |
| `clip_url` | 对应片段 MP4（COS）。直接丢 `<video src>` 从头播，命中台词在中间。 |
| `source_video_url` | **原片 MP4**（COS）。配合 `start_time` seek 可以**精确**跳到台词说出的那一秒 |
| `start_time` | 台词开始秒（相对于原视频 0 秒起算） |
| `end_time` | 台词结束秒 |
| `text` | 原台词文本 |
| `score` | CLIP 余弦相似度 [-1, 1]，通常 > 0.2 才有意义 |

### 5.5 错误

| 状态 | 场景 |
|---|---|
| 400 | `query` 为空 |
| 500 | OpenSearch 不可达 / CLIP 模型加载失败 |

### 5.6 前端最小集成

**方式 A：直接播片段 MP4**（简单，从 0 开始）
```html
<video src="{{ result.clip_url }}" controls></video>
<p>"{{ result.text }}" — {{ result.start_time.toFixed(1) }}s</p>
```

**方式 B：原片 seek 到台词起点**（精确，推荐）
```html
<video id="v" src="{{ result.source_video_url }}" controls></video>
<script>
  const v = document.getElementById('v');
  v.addEventListener('loadedmetadata', () => {
    v.currentTime = {{ result.start_time }};
    v.play();
  });
</script>
<p>定位到：{{ result.start_time.toFixed(1) }}s — "{{ result.text }}"</p>
```

### 5.7 和 `/search` 的区别

| 维度 | `/search`（CLIP 视觉） | `/search_subtitle`（台词语义） |
|---|---|---|
| 索引对象 | 每帧（1 fps 采样） | 每条 SRT cue（Whisper 产出） |
| 粒度 | 帧 → 片段（聚合后） | 单条台词（可能几秒到十几秒） |
| 返回主单元 | **可播放片段** `clip_url` | **精确时间戳** `start_time` + `end_time` |
| 文本输入编码路径 | CLIP text encoder → 视觉空间 | CLIP text encoder → **同一个** 视觉空间 |
| 支持图片 query | ✅ | ❌ |
| 典型 query | 场景/物体描述 | 具体台词 / 新闻主题 |
| p99 延迟 | 150-400 ms | 150-400 ms |

**可以并发调两个端点**前端自己合并结果，视觉匹配和语义匹配往往互补。

**注意**：本服务**不对外暴露任务入队接口**。任务由本地脚本投入 Redis 队列（见 §8 CLI 入口），本端点只用于轮询任务状态。

## 7. `GET /articles`

**用途**：拿已入库到 `clipquery_articles` 的文章列表，支持分页 + 按 title 搜索。不返 `paragraphs`（正文过大，详情接口才给）。

### 7.1 Query 参数

| 参数 | 类型 | 默认 | 范围 | 说明 |
|---|---|---|---|---|
| `offset` | int | `0` | `>= 0` | 分页起点 |
| `limit` | int | `20` | `1 - 100` | 每页条数 |
| `q` | string | 不传 | - | 非空则按 title match 搜索；不传或空则列全部 |

**排序**：按 `ingested_at` 倒序（最新入库的在前）。

### 7.2 请求示例

```bash
# 列最新 20 篇
curl 'http://localhost:8000/articles'

# 翻页
curl 'http://localhost:8000/articles?offset=20&limit=20'

# 按 title 搜
curl 'http://localhost:8000/articles?q=climate&limit=10'
```

### 7.3 响应 200

```json
{
  "total":   1234,
  "offset":  0,
  "limit":   20,
  "results": [
    {
      "id":            "a1b2c3d4e5f6a7b8",
      "title":         "China vows carbon neutrality by 2060",
      "url":           "https://news.cgtn.com/news/.../index.html",
      "cos_video_url": "https://video-metainsight-....cos.ap-beijing.myqcloud.com/ClipQuery/a1b2c3d4e5f6a7b8/video.mp4",
      "ingested_at":   "2026-11-09T09:34:12+00:00"
    }
  ]
}
```

`total` 是过滤后总数（用于分页）；结果本次最多返回 `limit` 条。

## 9. MCP 服务 `/mcp`

本服务通过 [Model Context Protocol](https://modelcontextprotocol.io) 暴露 **5 个只读工具**给 LLM 客户端（Claude Desktop / Cursor / Cline / MCP Inspector 等）。传输用 MCP 官方 **Streamable HTTP**（含 SSE，单端点），和 REST 共享同一个端口。

### 9.1 为什么 `/search` 不开 MCP 工具

`/search` 支持文本 + 图片混合查询，需要客户端上传 `multipart/form-data` 图片字节，MCP 的 JSON 工具调用不方便传二进制。所以**图片/多模态语义搜继续走原 REST `POST /search`**，MCP 只暴露纯文本接口。

### 9.2 工具清单

| 工具 | 对应 REST | 参数 | 用途 |
|---|---|---|---|
| `health` | `GET /health` | - | 健康检查 |
| `get_task` | `GET /task/{task_id}` | `task_id: str` | 查询任务状态 |
| `list_articles` | `GET /articles` | `offset: int = 0`, `limit: int = 20`, `q: str = None` | 已入库文章列表 |
| `get_article` | `GET /articles/{article_id}` | `article_id: str` | 文章详情（含正文） |
| `search_subtitle` | `POST /search_subtitle` | `query: str`, `top_k: int = 10` | 台词语义检索 |

工具实现直接调 Python 层（`get_queue()` / `get_article_store()` / `Retriever`），**不走 HTTP 回环**，比客户端自己调 REST 少一次 TCP + 一层序列化。

### 9.3 客户端接入

**Claude Desktop** `claude_desktop_config.json`：

```json
{
  "mcpServers": {
    "clipquery": {
      "transport": "http",
      "url": "http://<host>:8000/mcp"
    }
  }
}
```

**Cursor / Cline / 其他 MCP 客户端**：填入 URL `http://<host>:8000/mcp`，transport 选 "Streamable HTTP" 或 "SSE"。

**MCP Inspector 调试**（官方命令行工具，推荐冒烟）：

```bash
npx @modelcontextprotocol/inspector http://localhost:8000/mcp
```
- 列出工具：Tools → 应该看到 5 个
- 任选一个 call：例如 `list_articles(offset=0, limit=5)`

### 9.4 协议细节

- 端点：`POST /mcp`（会话建立 + 工具调用 + SSE 流）
- 协议版本：MCP 2024-11-05（Streamable HTTP）
- Session：由 FastMCP 的 session manager 维护，主进程 lifespan 启动时一并初始化
- 认证：当前**没有**鉴权层；上生产前应在前面套一层网关（Nginx auth_basic / Cloudflare Access / API Key 反代都行）

## 10. CLI 入口（任务投入的唯一入口）

容器镜像也带 `scripts/`，可以 `docker exec` 单独跑，调试用。

### 10.1 `scripts/crawl_one.py`

```bash
docker exec -it clipquery python scripts/crawl_one.py
```
- 只跑爬虫 pipeline（`process_one_article(url)`），不做向量入库。
- 产物：`news/<aid>/video.mp4` + COS 上的 `info.json / audio.mp3 / video.srt`，`clipquery_articles` 写入。

### 10.2 `scripts/pipeline_one.py`

```bash
docker exec -it clipquery python scripts/pipeline_one.py "https://news.cgtn.com/news/.../index.html"
```
- 端到端：爬虫 + 切片 + 编码 + 三索引。

### 10.3 `python -m clipquery.task.cgtn --run-once`

```bash
docker exec -it clipquery python -m clipquery.task.cgtn --run-once
```
- 立刻跑一次 CGTN 列表扫描，只把新 URL 入 Redis 队列，不执行。

## 11. Pydantic 模型

定义在 `clipquery/main.py`。

### 11.1 `SegmentOut` — `/search` 返回项
```python
class SegmentOut(BaseModel):
    clip_id: str
    article_id: str
    article_url: Optional[str] = None
    title: Optional[str] = None
    start_time: float
    end_time: float
    clip_url: str
    thumbnail: Optional[str] = None
    score: float
    hit_count: int
    best_frame_id: Optional[str] = None
    paragraphs: list[str] = []
```

### 11.2 `SubtitleHit` — `/search_subtitle` 返回项
```python
class SubtitleHit(BaseModel):
    article_id: str
    article_url: Optional[str] = None
    title: Optional[str] = None
    clip_id: Optional[str] = None
    clip_url: Optional[str] = None            # 对应片段 MP4

    text: str                                 # 原台词
    score: float
```

```python
class TaskStatusOut(BaseModel):

    article_url: Optional[str] = None

    video_path: Optional[str] = None
    frames_written: Optional[int] = None
    error: Optional[str] = None
    retry_count: int = 0
    created_at: Optional[str] = None
    updated_at: Optional[str] = None
    finished_at: Optional[str] = None
```

## 12. 任务消息契约（队列）

Redis list `ClipQuery:ingest:queue`，LPUSH / BRPOP。消息体 JSON：

```json
{
  "task_id":   "ingest-a1b2c3d4e5f6a7b8",
  "task_type": "ingest_cgtn_article",
  "payload":   {"article_url": "https://...", "article_id": "...", "_force": false}
}
```

### 11.1 task_type 总表

| task_type | payload | result（成功时） | 触发来源 |
|---|---|---|---|
| `ingest_cgtn_article` | `{"article_url", "article_id", "_force"?}` | `{"article_id", "video_path", "frames_written", "force"}` | `scripts/scan_cgtn.py` 或 `scripts/pipeline_one.py` |
| `ingest_path` | `{"video_path", "_force"?}` | `{"video_path", "frames_written", "force"}` | 本地脚本直调 `RedisQueue.enqueue()` |
| `ingest_upload` | `{"video_path", "_force"?}` | `{"video_path", "frames_written", "force"}` | （历史类型，当前无投入入口） |

**task_id 规范**：
- URL：`ingest-<sha1(article_url)[:16]>`。
- path/upload：`ingest-path-<sha1(video_path)[:16]>`。file 上传时 video_path 是 `/app/data/uploads/<uuid>.mp4`，每次 uuid 不同。

### 11.2 添加新 task_type

两步：

1. 在 `clipquery/task/executor.py` 的 `_DISPATCH` 加映射。
2. 写 `_run_my_new(payload: dict) -> dict`，抛异常会被统一 `mark_failed`。

## 13. Python 内部接口

### 11.1 `clipquery.queue.RedisQueue`

```python
from clipquery.queue import get_queue, TaskState, new_worker_id

q = get_queue()                                          # lru_cache 单例

# 入队（幂等）
doc = q.enqueue(task_id, task_type, payload, force=False)
# force=False：task_id 已存在且未终态 → 返回现状，不再 LPUSH
# force=True ：无视现状强制 LPUSH；payload 自动写入 "_force": true

# 消费
doc = q.pop(timeout=5)                                   # BRPOP，None 表示空队列

# 元数据
doc = q.get(task_id)                                     # dict with payload/result 已解包
q.mark_in_progress(task_id, worker_id)
q.mark_done(task_id, result={"frames_written": 60})
q.mark_failed(task_id, error="downloader timeout")
n = q.incr_retry(task_id)

# 分布式锁
ok = q.acquire_lock(task_id, worker_id, ttl_seconds=1800)
ok = q.refresh_lock(task_id, worker_id, ttl_seconds=1800)
ok = q.release_lock(task_id, worker_id)

# 健康
ok = q.ping()
n  = q.queue_length()

worker_id = new_worker_id("app")                         # app-<host>-<pid>-<rand4>
```

## 14. Redis key 一览

| key | 类型 | 用途 | TTL |
|---|---|---|---|
| `ClipQuery:ingest:queue` | list | 任务队列 | 永久 |
| `ClipQuery:task:<task_id>` | hash | 任务元数据 | 86400s（`redis_task_meta_ttl`），失败任务永久 |
| `ClipQuery:lock:<task_id>` | string | 执行互斥锁 | 1800s（`scheduler_task_ttl`） |

`project_name` 默认 `clipquery`，改成 `clipquery_prod` / `clipquery_test` 可在同一个 Redis 隔离多环境。

### 14.4 `clipquery_subtitles` — `/search_subtitle` 用

```json
{
  "settings": {"index": {"knn": true, "knn.algo_param.ef_search": 128}},
  "mappings": {
    "properties": {
      "embedding":   {"type": "knn_vector", "dimension": 512, "method": {...}},
      "article_id":  {"type": "keyword"},
      "clip_id":     {"type": "keyword"},   // 台词 mid 时间点落在哪个片段
      "cue_index":   {"type": "integer"},   // SRT 里的第几条 cue（1-based）
      "start_time":  {"type": "float"},     // 台词开始秒（相对于原视频）
      "end_time":    {"type": "float"},
      "duration":    {"type": "float"},
      "text":        {"type": "text"},      // 原台词；同时也支持兜底全文检索
      "video_path":  {"type": "keyword"},
      "ingested_at": {"type": "date"}
    }
  }
}
```

**文档 id** = `sha1(article_id:sub:<cue_index>)[:20]`，天然幂等。

**索引时**：`indexer.ingest_video()` 里 `_process_subtitles` 读 `news/<aid>/video.srt` → 过滤过短/空白 cue → 每条过 CLIP 文本编码 → bulk upsert。

**检索时**：`Retriever.search_subtitle(text, top_k)` CLIP 文本编码查询 → KNN → JOIN clip/article 元数据 → 返回 `SubtitleHit`。

## 17. 速率与成本

| 操作 | 典型耗时（CPU） | 主要成本 |
|---|---|---|
| `POST /search` | 150–400 ms | CLIP 文本编码 + 1 次 OpenSearch KNN（`clipquery_frames`） |
| `POST /search_subtitle` | 150–400 ms | CLIP 文本编码 + 1 次 OpenSearch KNN（`clipquery_subtitles`） + 1 次 mget JOIN |
| `GET /task/{task_id}` | < 10 ms | 1 次 Redis HGETALL |
| `GET /articles` | 20–60 ms | 1 次 OpenSearch search（match/match_all + sort） |
| `GET /articles/{article_id}` | 10–30 ms | 1 次 OpenSearch get |
| 本地脚本投入一条任务 | < 20 ms | 1 次 Redis pipeline（HGET + HSET + LPUSH） |
| 爬 1 篇（含下载 + Whisper） | 60–180 秒 | 网络 + Whisper |
| CLIP 抽帧 + 编码（1 分钟，60 帧） | 30–90 秒 | CPU |
| 端到端入库（1 分钟视频，CPU） | 2–5 分钟 | — |
