# ClipQuery 需求文档

> 版本：v0.3（引入片段切分，返回可直接播放的 MP4 片段）
> 更新：2026-11-06

---

## 1. 项目定位

**ClipQuery 是一个面向视频新闻库的语义检索服务**：输入一段自然语言（或一张参考图），返回库内与之语义最接近的**视频片段**（直接可播放的 MP4）+ 片段所属新闻的详情信息 + 详情页链接。

它的核心能力不是"找视频文件"，而是"找到视频里的一段可以直接播放的画面"。例如：

- `"一个人在海边奔跑"` → 返回某篇 CGTN 新闻的 00:12–00:18 片段
  - 一个可直接 `<video src="...">` 的 MP4 URL
  - 新闻标题、详情页 URL、正文段落
  - 命中帧缩略图

### 1.1 目标场景

- **央视 CGTN 新闻素材检索**：记者 / 编辑用自然语言或参考图在素材库里"按画面"找到片段。
- **历史素材复用**：节目组做新片时快速定位可复用的镜头。
- **后续可扩展**：按台词搜（Whisper 转录文本）、按人脸 / 物体过滤。

### 1.2 非目标（明确不做的事）

- 不做视频播放器 / 剪辑器，只做检索。
- 不做用户系统、权限、多租户，当前为内部工具。
- 不做大规模分布式集群调度，MVP 单节点 OpenSearch 即可。

## 2. 核心需求

### 2.1 数据接入（离线）

| ID | 需求 | 优先级 |
|---|---|---|
| D-1 | 从 CGTN transcript 列表页批量抓取：列表 → 详情 → MP4 + 字幕 + 正文 | P0 |
| D-2 | 支持单个文章 URL 抓取（服务化入口） | P0 |
| D-3 | 产物目录以 **URL hash（sha1 前 16 位）** 命名，保证幂等 | P0 |
| D-4 | 产物包含 `info.json` / `video.mp4` / `audio.mp3` / `video.srt` | P0 |
| D-5 | ASR 优先 Whisper，失败回退正文段落占位 | P1 |
| D-6 | 同一 URL 重复抓取自动跳过 | P0 |
| D-7 | **多任务并发安全**：同一 URL 阻塞等待，不同 URL 完全隔离 | P0 |

### 2.2 产物归档（对象存储 + 元数据索引）

| ID | 需求 | 优先级 |
|---|---|---|
| A-1 | **静态文件（video.mp4 / audio.mp3 / video.srt / info.json）上传到腾讯云 COS**，路径 `ClipQuery/<id>/<file>` | P0 |
| A-2 | **每帧缩略图上传 COS**，路径 `ClipQuery/<id>/thumbnails/<frame_id>.jpg` | P0 |
| A-3 | 本地**不保留**完整产物：上传完 COS 即删，入库完整个 `news/<id>/` 清空 | P0 |
| A-4 | **info.json 完整写入 OpenSearch 索引 `clipquery_articles`**，文档 id = article_id | P0 |
| A-5 | COS 上传幂等（对象已存在则跳过，info.json 除外，它每次覆盖） | P0 |
| A-6 | COS / OpenSearch 任一失败不中断流程，日志告警后继续 | P1 |

### 2.3 视频切片（入库阶段预切）

| ID | 需求 | 优先级 |
|---|---|---|
| C-1 | 入库时把原片 `video.mp4` 按**场景**切成若干独立 MP4 片段；场景过长时按目标长度二次拆 | P0 |
| C-2 | 片段时长控制在 `[clip_min_seconds, clip_target_seconds]`（默认 2–6 秒） | P0 |
| C-3 | 用 **PySceneDetect** 做场景检测；未安装 / 失败时回退**等长切片**保证可用 | P0 |
| C-4 | ffmpeg `-c copy` 流复制无损切片；copy 失败回退重编码保证兼容性 | P0 |
| C-5 | 每个片段上传 COS：`ClipQuery/<article_id>/clips/<clip_id>.mp4`，产物是**浏览器可直接播放的 MP4** | P0 |
| C-6 | 片段元数据（clip_id / start_time / end_time / clip_url / article_url / title / thumbnail）写入 OpenSearch `clipquery_clips`，文档 id = clip_id | P0 |
| C-7 | 每一帧 CLIP 向量入库时，记录它所属的 `clip_id`，用于在线检索直接聚合到片段 | P0 |

### 2.4 视频索引（离线 → 向量库）

| ID | 需求 | 优先级 |
|---|---|---|
| I-1 | 按固定 FPS 抽帧（默认 1 FPS，可配置） | P0 |
| I-2 | 每帧用 CLIP 编码为 512 维向量，入库前 L2 归一化 | P0 |
| I-3 | 向量和帧元数据（含 `article_id` / `clip_id` / `thumbnail` COS URL）写入 `clipquery_frames` | P0 |
| I-4 | 入库幂等：同一视频已入库则跳过；`--force` 强制重做 | P0 |
| I-5 | 命令行批量入库目录 | P0 |

### 2.5 在线检索（API）

| ID | 需求 | 优先级 |
|---|---|---|
| S-1 | `POST /search` 支持文本查询 | P0 |
| S-2 | `POST /search` 支持图片查询（以图搜视频） | P0 |
| S-3 | 支持文本 + 图片混合查询（向量求平均后归一化） | P1 |
| S-4 | 返回**可直接播放的片段**：`clip_url`（COS MP4） + `article_url`（CGTN 详情页） + `title` + `paragraphs` + 缩略图 + 片段时间段 + score | P0 |
| S-5 | 按 `clip_id` 聚合 KNN 命中帧，同片段多帧命中只返回一次（最高分） | P0 |
| S-6 | 任务投入由**本地脚本**完成（`scripts/pipeline_one.py` / `scripts/scan_cgtn.py` / `scripts/consume_one.py`），**服务端不对外暴露入队接口** | P0 |
| S-7 | `GET /task/{task_id}` 查询任务状态（queued / in_progress / done / failed） | P0 |
| S-8 | `GET /health` 健康检查，返回索引帧数 | P0 |

### 2.6 部署与运维

| ID | 需求 | 优先级 |
|---|---|---|
| O-1 | **所有路径基于项目根**，无硬编码绝对路径 | P0 |
| O-2 | 所有配置可通过 `CLIPQUERY_*` 环境变量覆盖 | P0 |
| O-3 | 跨平台：开发 Windows，部署 Linux | P0 |
| O-4 | 敏感凭据（OpenSearch / COS）通过 `.env` 注入，不进 Git | P0 |

```

│ 接口层 (clipquery/api/)                                       │
│   FastAPI: /search  /task/{id}  /health（只读，任务投入见脚本）│
└───────────────┬──────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────┐
│ 在线检索 (clipquery/search/)                                  │
│   Retriever: 文本/图片 → CLIP → OpenSearch KNN → 片段合并     │
└───────────────┬──────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────┐
│ 存储层 (clipquery/storage/ + clipquery/cos.py)                │
│                                                              │
│   OpenSearch:                                                │
│     clipquery_frames    (knn_vector + 帧元数据 + clip_id)    │
│     clipquery_clips     (片段元数据 + 可播放 clip_url)        │
│     clipquery_articles  (info.json 完整副本 + COS URL)       │
│                                                              │
│   腾讯云 COS (ap-beijing / video-metainsight-test-...):      │
│     ClipQuery/<id>/video.mp4     原片                        │
│     ClipQuery/<id>/audio.mp3                                 │
│     ClipQuery/<id>/video.srt                                 │
│     ClipQuery/<id>/info.json                                 │
│     ClipQuery/<id>/clips/<clip_id>.mp4     片段 MP4           │
│     ClipQuery/<id>/thumbnails/<frame_id>.jpg                 │
│                                                              │
│   本地（中间工作区，即传即删）：                              │
│     news/<id>/video.mp4（indexer 完成后清空整个目录）         │
│     data/thumbnails/*.jpg、data/clips/<id>/*.mp4（上传即删）  │
└───────────────▲──────────────────────────────────────────────┘
                │
┌───────────────┴──────────────────────────────────────────────┐
│ 离线处理                                                      │
│   scripts/ 爬虫 → news/<id>/*  → 上传 COS → 写 article 索引   │
│   clipquery/pipeline/                                        │
│     clipper: 场景检测 → ffmpeg 切片 → 上传 COS → 写 clips 索引│
│     indexer: 抽帧 → CLIP → 上传缩略图 → 写 frames（含 clip_id）│
└──────────────────────────────────────────────────────────────┘
```

### 3.1 单向数据流

1. **爬虫** 抓 CGTN → 本地 `news/<id>/` 作临时工作区 → **上传 COS** → 立即删 audio/srt/info → 写 `clipquery_articles`（含 COS URL）→ `video.mp4` 等 indexer 用完再清
2. **Clipper** 场景检测 `video.mp4` → ffmpeg 切片 → **片段 MP4 上传 COS** → 写 `clipquery_clips`（含可播放 URL）
3. **Indexer** 抽帧 → CLIP 编码 → **缩略图上传 COS** → 写 `clipquery_frames`（每帧绑定 `clip_id`）
4. **API** 查询 → CLIP 编码 → KNN → 按 `clip_id` 聚合 → mget `clipquery_clips` + `clipquery_articles` → 返回片段 + 新闻详情

### 3.2 技术选型

| 组件 | 选型 | 理由 |
|---|---|---|
| 向量模型 | `clip-ViT-B-32`（sentence-transformers） | 文本+图像同向量空间 |
| 向量库 | AWS OpenSearch 2.x `knn_vector` | 既有基础设施复用 |
| KNN 引擎 | nmslib + hnsw + cosinesimil | AWS 托管域默认最稳 |
| 对象存储 | **腾讯云 COS**（ap-beijing） | 国内访问快、按量计费 |
| 抽帧 | OpenCV 固定 FPS | MVP 够用，后续升 PySceneDetect |
| ASR | OpenAI Whisper CLI | 开源、本地跑 |
| 视频下载 | ffmpeg 两阶段（m3u8 → ts → mp4） | 兼容 CGTN 的 HLS 切片 |
| API | FastAPI + BackgroundTasks | 轻量、自带 OpenAPI 文档 |

## 7. 并发与一致性

### 7.1 爬虫层

- **文章级文件锁** `news/<id>/.lock`，跨进程跨平台（msvcrt / fcntl）
- **Double-checked locking**：入锁后二次检查 `info.json`
- **ts 临时目录独占**：`tempfile.mkdtemp`，兄弟任务不互扰
- **原子写 info.json**：`write .tmp → os.replace`

### 7.2 COS 上传

- 上传幂等：`exists()` 预检，命中则跳过
- 大文件（>5MB）自动分片上传
- 单个文件失败降级：记日志但不中断主流程
- `info.json` 强制覆盖（元数据可能变更）

### 7.3 索引层

- `clipquery_frames` 文档 id = `sha1(video_path:frame_index)[:20]`，`upsert` 幂等
- `clipquery_articles` 文档 id = `article_id`（URL 的 sha1[:16]），`upsert` 幂等

### 7.4 未覆盖

- Whisper / ffmpeg 并发资源争抢（下一版加信号量）
- 跨集群备份（COS 单可用区）

## 8. 运行指南

### 8.1 本地开发

```bash
# 1. 配置：复制模板后填实际值
cp .env.example .env
vim .env    # 至少改 OpenSearch 密码 + COS 凭据 + Redis 密码

# 2. 构建 + 启动（容器内 8000 → 宿主机 8008）
docker build -t clipquery:latest .
docker run -d --name clipquery -p 8008:8000 \
  -v $PWD/.env:/app/.env:ro \
  -v clipquery-news:/app/news \
  -v clipquery-data:/app/data \
  clipquery:latest

# 3. 入库（服务端无 HTTP 入队接口，所有任务从本地脚本进）
docker exec -it clipquery python scripts/pipeline_one.py \
  "https://news.cgtn.com/news/.../index.html"
```

### 8.2 服务器部署（Linux）

```bash
# 凭据统一走 .env，不要 export
cp .env.example .env
chmod 600 .env
vim .env

docker build -t clipquery:latest .
docker run -d --name clipquery -p 8008:8000 \
  -v $PWD/.env:/app/.env:ro \
  -v clipquery-news:/app/news \
  -v clipquery-data:/app/data \
  --restart unless-stopped \
  clipquery:latest
# ⚠️ 容器内 uvicorn --workers 1 是强制的：MCP session manager 是进程级单例。
# 水平扩请起多个容器，Redis 锁 + BRPOP 自动互斥。
# 端口说明：容器内固定 8000，宿主机映射 8008 对外；多副本横向扩可用 8009/8010/...
```

## 10. 已知限制

- **CGTN 爬虫与页面结构强耦合**：改版需重新适配 XPath
- **CLIP 中文语义偏弱**：`clip-ViT-B-32` 以英文为主
- **单机瓶颈**：MVP 未分布式入库，视频库 > 10 万条需引任务队列
- **测试凭据默认值在代码中**：生产务必 env 覆盖
- **COS 与 OpenSearch 跨区**：OpenSearch 在 ap-southeast-1，COS 在 ap-beijing，缩略图/视频 URL 返回给前端走 COS CDN；上传流量跨区走公网
