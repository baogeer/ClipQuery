# ClipQuery 架构文档

> 版本：v0.5（单容器版）
> 更新：2026-11-09

本文档是**开发者视角**的架构参考。面向需求和产品定位请看 [需求文档](./需求文档.md)。

---

## 1. 定位

ClipQuery 是一个面向视频新闻库的语义检索服务。FastAPI 进程只做**只读 API**，所有写入由本地脚本驱动：

- **在线检索（HTTP）**：`/search` → CLIP 查询编码 → OpenSearch KNN → 聚合 → 返回可直接播放的片段。
- **状态查询（HTTP）**：`/task/{id}` 从 Redis 读元数据 hash。
- **任务入队（本地脚本，不走 HTTP）**：`scripts/scan_cgtn.py` / `scripts/pipeline_one.py` 直调 `RedisQueue.enqueue()`，带幂等三道闸 + force 清理。**服务端不对外暴露任何入队接口**。
- **后台消费（本地脚本）**：`scripts/consume_one.py` 从 Redis 队列 BRPOP 拿任务，获取 Redis 分布式锁，执行完整入库流水线。

多实例水平扩时：
- 服务层无状态（只读 REST + MCP），多副本直接起。
- 多台开发机同时跑 `scripts/consume_one.py` 时，`BRPOP` 保证一条任务只被一个进程拿到，`ClipQuery:lock:<task_id>` 的 `SET NX PX` 再做一道执行期互斥。
- 所有状态都在 Redis + OpenSearch，服务容器挂了随便重启。

## 3. 调度与执行

### 3.0 入队前的幂等三道闸

所有入队路径（`scripts/scan_cgtn.py`、`scripts/pipeline_one.py`）都在 `RedisQueue.enqueue()` 之前过 `clipquery.task.dedupe` 的检查：

| 闸 | 检查 | 命中后 |
|---|---|---|
| 1 | Redis `ClipQuery:task:<task_id>` state ∈ {queued, in_progress} | 已在队列或正在执行 |
| 2 | Redis `ClipQuery:task:<task_id>` state = done | 24h 内处理过 |
| 3 | OpenSearch `clipquery_articles.exists(article_id)` | 长期记录；Redis meta TTL 过期后兜底 |

path / upload 任务没有 article_id，走等价两道闸：Redis meta + `clipquery_frames` 按 `video_path` 的帧数 > 0。

**force=True 时三道闸全部跳过**，但入队前必须先调 `clipquery.task.purge`：

| purge 对象 | 删除内容 |
|---|---|
| `purge_article(aid)` | `clipquery_articles` / `_frames` / `_clips` 三索引 + COS `ClipQuery/<aid>/*` + 本地 `news/<aid>/` |
| `purge_video_path(path)` | `clipquery_frames` 按 `video_path` 删 |

purge 全部"尽力而为"，某一步失败只写 `purge_report["xxx"] = "error: ..."` 不中断 enqueue。

执行端（`executor._run_cgtn` / `_run_path`）在 `payload._force=True` 时把 `ingest_video(skip_if_exists=False)` 传下去，强制重跑切片 + 抽帧编码。

### 3.1 调度（本地脚本层）

当前版本服务进程**不再承担任何调度 / 消费**，这些由本地脚本完成：

- `python scripts/scan_cgtn.py` —— 跑一次 `clipquery.task.cgtn.tick()`，拉 CGTN 列表 → 入 Redis 队列。想定时就套 crontab / systemd-timer。
- `python scripts/consume_one.py [--all]` —— BRPOP 一条/所有任务并执行。

两者都直接调 Python 层（见 §3.2 / §3.3），不走 HTTP。分布式锁由 `ClipQuery:lock:<task_id>` 保证同一任务只被一人消费。

### 3.2 任务扫描逻辑：`clipquery.task.cgtn.tick()`

脚本调用：

1. `crawl_transcript_page()` 拉 https://www.cgtn.com/transcript 列表页。
2. 对每个 URL 计算 `article_id = sha1(url)[:16]`，`task_id = ingest-<article_id>`。
3. `check_article_duplicate(aid, task_id)` 三道闸 → 跳过已处理。
4. 剩下的 URL LPUSH 到 Redis 队列，`force=False`，state=`queued`。

**不执行任务**，只做入队。执行在 3.3 的消费端。定时任务永远 force=False。

### 3.3 本地消费：`scripts/consume_one.py` → `executor.consume_once`

`consume_once(worker_id, timeout)`：
1. `RedisQueue.pop(timeout=5)` → `BRPOP ClipQuery:ingest:queue 5`。
2. 拿到 task_doc 后 `execute_task(doc, worker_id)`。
3. 队列空则 timeout 返回 None，继续下一轮。

`execute_task(doc, worker_id)`：
1. `RedisQueue.acquire_lock(task_id, worker_id, ttl=1800)` — `SET ClipQuery:lock:<task_id> <worker_id> NX PX 1800000`。失败（他人持锁）→ 直接返回。
2. `mark_in_progress(task_id, worker_id)`：更新 meta hash。
3. `_run_with_lock_refresh()` 起一个后台线程每 60s 刷新锁 TTL。
4. 按 `task_type` 分发，`payload._force` 转成 `skip_if_exists=not force`：
   - `ingest_cgtn_article` → `process_one_article(url)` 爬 + 下视频 + ASR + COS → `ingest_video(skip_if_exists=…)`。
   - `ingest_path` / `ingest_upload` → `ingest_video(skip_if_exists=…)` 直接入库。
5. 执行完 `mark_done(result)` 或 `mark_failed(error)` + `incr_retry`。
6. `release_lock(task_id, worker_id)`（Lua 脚本校验 value 匹配后再 DEL）。

## 4. 任务状态机

```
┌─────────┐  LPUSH   ┌─────────┐  BRPOP+lock OK  ┌─────────────┐  mark_done  ┌──────┐
│ (none)  │ ──────▶ │ queued  │ ──────────────▶ │ in_progress │ ─────────▶  │ done │
└─────────┘          └────▲────┘                 └──────┬──────┘             └──────┘
                          │                             │ mark_failed
                          │                             ▼                     ┌────────┐
                          │                        retry_count +1             │ failed │
                          │ 锁 TTL 过期 + 新 LPUSH                            └────────┘
                          │ (实例挂了 / 任务超时)                                  ▲
                          └────────────────────────────────────────────────────────┘
```

- **enqueue** 幂等：同 `task_id` 且未终态 → 返回现状、不再 LPUSH；已终态 → 新建 queued + LPUSH（支持重试）。
- **锁**：`SET NX PX`，value = worker_id，释放用 Lua 脚本校验 value 匹配后 DEL，避免误删别人的锁。
- **锁刷新**：执行过程中每 `scheduler_task_heartbeat` 秒（默认 60s）用 Lua `PEXPIRE` 延期。锁最长活 `scheduler_task_ttl` 秒（默认 1800s）。
- **元数据 TTL**：meta hash 每次更新都会 `EXPIRE` 刷到 `redis_task_meta_ttl` 秒（默认 86400s = 24h）。

## 5. 爬虫流水线（`clipquery.website.cgtn.pipeline.process_one_article`）

```
process_one_article(article_url)
  │
  ├─ parse_transcript_detail(url)             # title / paragraphs / m3u8
  ├─ article_id = sha1(url)[:16]
  ├─ article_dir = news/<article_id>/
  │
  ├─ article_lock(article_dir):               # fcntl / msvcrt 文件锁
  │   ├─ 二次检查 info.json 存在 → 直接返回已有 meta
  │   │
  │   ├─ download_m3u8_as_mp4()               # m3u8 → ts → mp4
  │   ├─ export_audio_mp3()                   # ffmpeg 抽 128k mp3
  │   ├─ Whisper → video.srt（或 paragraphs 兜底）
  │   │
  │   ├─ cos.upload_file(video.mp4)           # 留本地给 indexer 用
  │   ├─ cos.upload_and_delete(audio.mp3)     # 上传后 unlink
  │   ├─ cos.upload_and_delete(video.srt)     # 同上
  │   │
  │   ├─ write info.json (atomic: .tmp + replace)
  │   ├─ cos.upload_file(info.json)
  │   ├─ article_store.upsert(article_id, meta)
  │   │
  │   └─ return meta
```

**事务性**：
- 文件系统层：`os.replace` 保证 `info.json` 原子可见。
- COS 层：单对象上传原子；多对象之间非原子。
- OpenSearch 层：`upsert` 以 article_id 为主键，重跑直接覆盖。

## 6. 向量入库流水线（`clipquery.pipeline.indexer.ingest_video`）

```
ingest_video(news/<aid>/video.mp4, article_id)
  │
  ├─ _infer_article_id()                      # 没传就用父目录名
  ├─ skip_if_exists and vector_store.video_frame_count() > 0 → skip  # 幂等
  │
  ├─ _process_clips():                        # 切片
  │   ├─ cut_clips(video)                     # PySceneDetect + ffmpeg
  │   ├─ for clip: cos.upload_and_delete() → cos URL
  │   ├─ clip_store.upsert_many(clip_docs)
  │   └─ rmtree(data/clips/<article_id>/)
  │
  ├─ for batch in iter_frames(video, fps=1.0, max_side=384):
  │   ├─ vecs = encoder.encode_images(batch)  # CLIP 批量
  │   ├─ for frame:
  │   │   ├─ save_thumbnail() → data/thumbnails/<fid>.jpg
  │   │   ├─ cos.upload_and_delete()
  │   │   └─ clip_id = find_clip_for_timestamp(clips, frame.ts)
  │   └─ vector_store.add(ids, vecs, metadatas)   # bulk upsert
  │
  ├─ vector_store.refresh()                   # 刚入库就查得到
  └─ shutil.rmtree(news/<aid>/)               # 彻底归零
```

**关键设计**：
- `skip_if_exists=False`（force）时跳过幂等信号，直接重跑。
- 先切后编：帧和片段用 timestamp 关联，必须先有片段窗口才能给帧打 `clip_id`。
- COS 失败降级：单对象失败只打 WARN，不中断主流程。

## 7. 关键决策

### 7.1 服务与数据处理分离

- **服务容器**只做只读 API（REST + MCP），无 CPU 重活，可长期跑在小机器上。
- **数据处理**（爬虫 / Whisper / CLIP 编码 / 索引写入）全部由 `scripts/*.py` 在开发机或专用算力机上按需跑，不占服务 CPU。
- 两边连同一个 Redis + OpenSearch + COS，脚本处理完服务侧 `/search` 立即可查。
- 服务容器要水平扩直接起多副本；多台算力机并发跑 `scripts/consume_one.py` 由 Redis 锁 + BRPOP 保证互斥。

### 7.2 为什么用 Redis 做队列

- `BRPOP` 原生阻塞，新任务入队 → 消费端立刻接到，端到端延迟 < 1s。
- `SET NX PX` 一条命令就是分布式锁。
- 公司已有 ElastiCache for Redis，不新增组件。

### 7.3 为什么任务元数据也存 Redis

- 任务状态高频读（前端轮询）、低频写，和 Redis 读写模型契合。
- 24h TTL 自动清理，不需要维护历史索引。
- 想要长期审计可以订阅 Redis `__keyspace__` 事件转写 OpenSearch，但不是 MVP 范围。

### 7.4 为什么是三个 OpenSearch 索引

**候选方案**：所有数据塞 `clipquery_frames`，用 `doc_type` 字段区分。

**选择三索引的理由**：
- mapping 清晰：knn_vector 很重，塞进 article 文档会浪费存储。
- 查询模式不同：frames 永远 KNN；clips 永远 mget；articles 永远 get by id。
- 删除成本低：想重建向量只需重建 `frames`，不碰文章和切片。

### 7.5 为什么先切片再编码

**候选方案**：先编码所有帧，查询时再按命中帧动态切片。

**选择"先切片"**：
- 查询响应延迟 < 500ms 目标下，不能把 ffmpeg 切片放在请求路径上。
- 前端拿到 `clip_url` 可以立刻 `<video src=...>` 播放。
- 切片是预先付费（入库慢），换查询免费。

## 8. 并发与一致性

### 8.1 多实例并发

| 场景 | 机制 | 结果 |
|---|---|---|
| 多台开发机都在 BRPOP 同一队列 | Redis 保证 BRPOP 原子 | 一条任务只被一个 consume 进程拿到 |
| 两个实例偶然拿到同 task_id | `acquire_lock` 失败 → 跳过 | 只一人执行 |
| 实例执行中进程死亡 | 锁 TTL 30 分钟后自动过期 | 下次 enqueue 或重入队时别的实例拿锁 |
| 同一 video.mp4 并发 ingest_video | 本地文件锁 + `video_frame_count > 0` | 后者跳过 |

### 8.2 锁超时处理

- 心跳刷新：执行中每 60s 刷新 `PEXPIRE`，确保长任务不被误释放。
- 锁 TTL：最长 1800s。单个入库任务极少超过，超过说明进程卡死或宕机。
- 超时后：锁自动过期，别的实例下次拿到同 task_id 时能顺利抢到。

## 9. 可观测性

**已有**：
- `/health` 返回 Redis 连通 + 队列长度 + 库中帧数 + worker_id。
- Python logging 走 stdout，`docker logs` 可见。
- Redis 本身：`LLEN ClipQuery:ingest:queue` / `KEYS ClipQuery:task:*` / `GET ClipQuery:lock:*`。

**未做**：
- 无 metrics / trace。
- 无死信队列（永久失败的 task 只会留在 Redis meta hash 直到 TTL）。

## 10. 扩展点

| 需求 | 改动点 |
|---|---|
| 加 Token 鉴权 | `clipquery/main.py` 加 `Depends(verify_token)` |
| 多语言查询 | `encoder.encode_text()` 换多语言 CLIP（如 M-CLIP） |
| 搜索加过滤条件 | `vector_store.query` 支持 `filter` 参数 + mapping 加字段 |
| 任务完成推送 | 加 SSE 端点 `/task/{id}/stream`，订阅 Redis Pub/Sub |
| 接新来源（新华社、CCTV 等） | 新建 `clipquery/website/<name>/pipeline.py`；在 `clipquery/task/<name>.py` 加 `tick()`；在 `_register_scheduled_jobs` 里 `add_task(...)` |
| 换向量模型（不同维度） | `encoder.py` + `config.embedding_dim`；Dockerfile 的 `snapshot_download` 换 repo；删 `clipquery_frames` 重建 |
| 替换 COS 为 S3 | 新建 `clipquery/s3.py` 和 `cos.py` 同接口；config 加开关 |
| 入库任务加重试上限 | `executor.execute_task` 判 `retry_count > N` 改入死信队列 |
